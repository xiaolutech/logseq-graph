# Commit message rule, and the machine check for it

## The rule

A commit subject names the area and the user-visible change:

```
<area>: <user-visible change in lowercase, no trailing period>
```

- `<area>` is one of `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`,
  `test`, `merge`, `wip` — optionally with a scope: `feat(server): ...`, `build(graph): ...`.
  `chore` is in the list because the history already uses it (`chore: refuse a hot-path commit
  that carries no performance row`); new commits should prefer the more specific areas.
- The subject states what the repository gains, not the implementation step: `docs: the performance
  rows name the commits they describe`, not `docs: update PERFORMANCE.md`.
- English only. The body, when there is one, explains why, not what the diff already says.
- A `merge` subject names the decision the merge records: `merge: where a per-edit write's time goes`.

## Why a check exists at all

`CONTRIBUTING.md` stated this style with no machine behind it. `scripts/check_commit_msg.py` is the
machine, in two places: the `commit-msg` hook reads the message file git passes and refuses a
subject that does not parse, and the `pre-push` hook re-checks every commit the push carries —
because a branch with three old-style commits can still pass the local hook for its fourth.

```sh
python3 scripts/check_commit_msg.py .git/COMMIT_EDITMSG      # one message, as git hands it over
python3 scripts/check_commit_msg.py --range origin/main...HEAD  # every commit a push carries
```

The range mode fails closed: a base ref that does not resolve (a clone that never fetched) is a
refused push with `VERDICT=BAD_RANGE`, not a silent pass.

The check is deliberately narrow. It validates the shape above and nothing else: no length limit, no
body rules, no banned words. A rule that rejects half the real history teaches people to bypass it.

## Exemptions

- **Merge commits** (`Merge branch ...`, `Merge remote-tracking branch ...`) are generated by git and
  skip the check.
- **Reverts** (`Revert "<original subject>"`) skip it, even though a hand-written `revert:` subject
  also passes.
- **Fixup/amend commits** (`fixup! ...`, `squash! ...`) skip it: their subject quotes another
  commit's, and they are rewritten before landing anyway.

## What it checks

1. The first line exists and is not blank.
2. It is not one of the three generated forms above.
3. It matches `^<area>(\(<scope>\))?: .`, where `<area>` is the list above, `<scope>` is
   `[a-z0-9_-]+`, and `.` requires at least one character after the colon-space.
4. The subject is a single line (the body starts after one blank line; a subject that runs on is a
   formatting bug the editor usually causes, so the check names the line).
